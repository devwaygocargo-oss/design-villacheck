# คู่มือ User — Phase 1 remediation candidate

สถานะ: ฉบับร่างสำหรับ source รอบ remediation วันที่ 6 พฤศจิกายน 2026 ยังไม่ใช่คู่มือรับรอง Production ภาพเป็นระบบจริงบน Local กับข้อมูลสังเคราะห์ ไม่ใช่หลักฐาน Staging หรือการส่ง OTP จากผู้ให้บริการจริง

1. **สมัครและยืนยันบัญชี** สร้างบัญชี User ด้วยชื่อ อีเมล และรหัสผ่าน หรือใช้ Email OTP, SMS OTP และ provider ที่ระบบเปิดใช้งาน บัญชีรหัสผ่านใหม่ยังไม่ถือว่ายืนยันอีเมลแล้ว และยังส่งรีวิวไม่ได้จนมีหลักฐานยืนยันตัวตนตาม flow ใช้บัญชีเดิมเมื่อเข้าสู่ระบบซ้ำ รหัส OTP และคำขอมีอายุและจำนวนครั้งจำกัดตามหน้าจอ การตอบรับคำขอไม่ใช่หลักฐานว่าส่งรหัสสำเร็จแล้ว
2. **ตรวจข้อมูลก่อนโอน** ค้นหาและเลือกที่พัก ตรวจชื่อ รูป จังหวัด และสถานะ กรอกเลขบัญชีที่ได้รับจากผู้ให้บริการเพื่อให้เซิร์ฟเวอร์เปรียบเทียบ ระบบไม่ส่งเลขบัญชีหรือเบอร์โทรเต็มกลับมา ผล MATCH หมายถึงตรงกับทะเบียนเท่านั้น MISMATCH หมายถึงไม่ตรง ผลลัพธ์ไม่ใช่การรับประกันธุรกรรมหรือการจอง
3. **ประวัติการเปรียบเทียบ** ผลที่เปรียบเทียบสำเร็จมีเลขอ้างอิง RGC และเปิดประวัติจากหน้าตรวจข้อมูลก่อนโอนได้ ประวัตินี้แยกจาก Checks รุ่นเดิมและไม่เก็บเลขบัญชีที่กรอก หากทะเบียนเปลี่ยนหรือ view หมดอายุ ต้องเลือกที่พักใหม่
4. **รีวิว** ต้องยืนยันอีเมลหรือเบอร์โทรก่อนส่ง และรีวิวที่พักของตนเองไม่ได้ ทุกแพ็กเกจส่งเข้า pending รอ Admin ตรวจ คะแนน pending/rejected ไม่รวมคะแนนเฉลี่ย ส่งซ้ำที่พักเดิมไม่ได้ และมี rate limit ผลไม่อนุมัติไม่แสดงสาธารณะ
5. **แจ้งปัญหา** เปิดจากหน้าที่พักเพื่อผูก QR ระบบใช้ข้อมูลที่พักจริงจาก QR/ID และไม่รับคู่ที่ขัดกัน ถ้าเข้าสู่ระบบ ผู้ดูแลเห็นตัวตนจากบัญชี ผู้ใช้ทั่วไปไม่เห็นตัวตนผู้แจ้ง ส่งแบบไม่เข้าสู่ระบบได้และระบุเป็น Anonymous
6. **คำขอข้อมูลส่วนบุคคล** เปิดข้อมูลบัญชี เลือก Access, Correction หรือ Deletion แล้วส่งคำขอด้วย session ของตนเอง ติดตามสถานะรอตรวจสอบ/กำลังดำเนินการ/เสร็จสิ้น/ปฏิเสธและผลตรวจได้ การส่งคำขอหรือการเปลี่ยนสถานะไม่ลบข้อมูลหรือส่งออกข้อมูลอัตโนมัติ เจ้าหน้าที่ต้องตรวจตัวตน ขอบเขต และการเก็บรักษาก่อนดำเนินการจริง

รอรับมอบ: ทดสอบบน Staging รุ่นที่ตรงกับ source, การรับ OTP จริง, ภาพขั้นตอนยืนยันจากผู้ทดสอบที่ยินยอม และการตรวจเนื้อหาโดยผู้รับผิดชอบ

VC-20 ฉบับปรับปรุง: เลือก “สมัคร Merchant” จากเมนูบัญชีผู้ใช้ กรอกข้อมูลธุรกิจ ช่องทางติดต่อ ข้อมูลบัญชีรับเงิน และยอมรับเงื่อนไข เมื่อส่งใบสมัครครบสำเร็จจะได้รับ Merchant capability โดยใช้ User ID เดิมและคงข้อมูล/ประวัติเดิม การตรวจเอกสารและอนุมัติที่พักแยกจากสิทธิ์เข้าพื้นที่ Merchant ห้ามใช้บัญชีผู้อื่นหรือสร้างบัญชีซ้ำ หลังสมัครสลับพื้นที่ User/Merchant ได้ด้วย session เดียว การออกจากระบบยุติทั้งสองพื้นที่ คู่มือนี้เป็น candidate ตาม source Staging ล่าสุด การยืนยัน live OTP/OAuth ต้องมีหลักฐานแยกจากบัญชี QA
